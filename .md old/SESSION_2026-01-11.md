## ✅ Completed Work

### 1. Processor/Supervisor System Validation
**Problem:** Processor wasn't detecting words from Duolingo curriculum (919 lexemes)

**Root Cause:** POS (part-of-speech) mismatch
- LLM extracts proper linguistic tags: `PRON`, `VERB`, `ADJ`
- Duolingo words imported with generic `GENERAL` tag
- Exact match requirement failed: `(lemma='хочу', pos='VERB')` vs DB `(lemma='хочу', pos='GENERAL')`

**Solution Implemented:**
- Added fallback matching logic in `supervisor-functions.ts` and `supervisor.ts`
- First attempts exact POS match, then tries `GENERAL` pos
- Now successfully matches all 919 Duolingo words

**Test Results:**

## 📝 Technical Decisions Made

### Why Ministral-3:14b?
- **Pros:** Better instruction following, more capable reasoning
- **Cons:** Larger (11GB), slower cold start, occasional JSON issues
- **Verdict:** Keep for conversation quality, add pre-warming to mitigate startup delay

### Why GENERAL pos fallback?
- **Alternative:** Re-import Duolingo with proper POS tags
- **Decision:** Fallback is non-invasive, works with any curriculum source
- **Benefit:** Future-proof for Anki, custom CSV, frequency lists

### Why mixed-mode prompts?
- **Alternative:** Pure immersion (100% target language)
- **Decision:** 80/20 balance makes learning more accessible
- **User feedback:** "More fun to talk to"

### Why JSON cleaning over structured output?
- **Alternative:** Use function calling or schema validation
- **Decision:** Quick fix, works with OpenAI-compatible API
- **Future:** Consider LangChain for structured output if issues persist
